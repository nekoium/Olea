## Implemented interface

- **OBSERVED**: `claude_start` and `claude_command` add a distinct Claude session alongside existing Pi/Codex sessions, sharing the two-session capacity and startup reservations. Supported Claude commands are `prompt`, `get_messages`, and `abort`; ordinary `stop` and backend shutdown close owned processes. Android exposes Claude in the existing conversation chooser, Anthropic provider dialog, installation/update menu, transcript, and cancellation path.
- **OBSERVED**: Stock CLI arguments use `--print --input-format stream-json --output-format stream-json --verbose --include-partial-messages`. Startup sends the supported `control_request` / `initialize` exchange; cancellation sends `control_request` / `interrupt`. No private CLI patch, agent fork, SDK dependency, or agent port was added.
- **OBSERVED**: Each conversation retains an immutable agent/workspace identity, a UUID, and a canonical persistent home under `/sessions/claude/<olea-session>/home`. `/sessions/claude/<olea-session>/session.json` records UUID, canonical workspace/home, and whether a submission was reserved. Reserved sessions reopen with `--session-id`; existing canonical stock transcripts reopen with `--resume` and the same UUID/home, never `--fork-session` or a copied home.
- **OBSERVED**: Submission uncertainty is checkpointed before writing a prompt. No automatic prompt replay or restart occurs. A submitted checkpoint with no canonical transcript fails explicitly with `claude_resume_history_missing`; it does not silently make a fresh conversation. History reads stock JSONL under the persistent home, follows the active leaf's parent chain, excludes sidechains, and bounds display history. Missing/oversize/unreadable display history does not replace canonical state; the saved Android display remains available where appropriate.
- **OBSERVED**: Linux cleanup uses observed process identities and owned descendant snapshots before signalling. Root/descendant verification is reported separately; Windows fixture cleanup does not claim Linux descendant proof. Startup cancellation waits for settlement and cannot publish a late session.
- **OBSERVED**: Shared authenticated Android phone tools are registered through the existing local MCP helper using `--strict-mcp-config`. This registers capability only; this worker made no real Claude phone-tool calls.

## Installation, provider configuration, and packaging interface

- **OBSERVED**: Explicit install runs ordinary upstream `npm install -g --prefix /opt/agents @anthropic-ai/claude-code@2.1.292`; explicit update selects `latest`. Version receipts reuse the existing `/root/.olea/<agent>-version.txt` mechanism. Claude is optional and is not automatically selected or installed by this change.
- **OBSERVED**: The backend defaults to `/opt/agents/bin/claude`, with optional `OLEA_CLAUDE_ENTRY` override. It discovers `/root/.olea/claude-provider.json`, or the explicit `OLEA_CLAUDE_PROVIDER_CONFIG` path. The Android dialog writes `{baseUrl, model, apiKey}` in that private provider file. No `runtime/linux.sh`, `Environment.kt`, or archive interface change is needed.
- **OBSERVED**: Provider validation requires HTTPS, no URL credentials/query/fragment, a nonempty bounded model ID, and a nonempty API key without line breaks. Claude receives the endpoint/model and a supported `apiKeyHelper`; generated settings, normal child environment, tool subprocess configuration, and process arguments do not contain the key. The helper reads only the configured provider file. Server output redacts the configured key. No credential stores or supplied temporary credentials were opened by this worker.
- **OBSERVED**: The Claude child starts with a restricted inherited environment, a separate `HOME`/`CLAUDE_CONFIG_DIR`, explicit settings sources, explicit MCP config, disabled automatic updater/nonessential traffic, and `API_MAX_RETRIES=0`. The upstream `IS_SANDBOX=1` environment accommodation is set because PRoot presents uid 0 while remaining an ordinary Android app; this does not assert filesystem isolation or Android root authority. Bypass permissions matches the approved broad app authority.

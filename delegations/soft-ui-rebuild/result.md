## Implementation

**OBSERVED**:

- `SoftTheme.kt` contains typed exact role values for green, purple, blue, rose, ochre and graphite, light/dark, including semantic and terminal roles. Green is both the new-preference and invalid-ID fallback. Settings stores `palette` independently of `appearance`, `fresh-chat`, setup and draft keys.
- `FlatUi.kt` supplies quiet rows, compact preference rows, paper groups/inputs, restrained notices/status badges, a two-column named swatch grid with selection semantics, drawn icons, quiet bottom destinations and 48 dp targets. Terminal extra keys retain 48 dp widths on narrow screens through horizontal scrolling.
- `OleaApp.kt` groups agent actions with their agent, keeps files/terminal on contextual workspace routes, uses management Back navigation, moves diagnostics behind disclosure, and uses bottom sheets for choices/details/confirmation. Main destinations disappear while the real IME is open. Existing navigation, first-send ordering and explicit reconnect/STOP bindings remain.
- `ConversationUi.kt` and `SoftConversation.kt` join draft setup to the composer, lock identity after first send, use asymmetric user bubbles, assistant headings/body/code, expandable selectable tools and contextual Needs-you controls. Accepted/rejected send callbacks retain their previous ordering and draft semantics. A small bounded Markdown presentation parser handles headings, fenced code, bold and inline code; other syntax remains readable literal text. No new agent protocol is introduced.
- `PhoneAccessUi.kt` / `PhoneAccessActivity.kt` use the same palette and components with real Android status, grant routes and consent. Broad shared-file access is separately visible. `SharedFolderActivity.kt` receives the same presentation and saved palette; this narrow extra UI file was necessary because it is the actual connected-workspace entry omitted from the brief's starting-file list. Its permission checks, directory access and return contract are unchanged.
- `TerminalUi.kt` / `terminal.html` use exact terminal roles, native monospace/font scaling, themed extra keys/footer, bounded drawing and resize-aware xterm. WebView file/content/network restrictions, exact resource allowlist, untrusted-output handling and PTY/input/output transport remain. Palette updates change xterm options in place, without creating a shell or restarting the backend.
- `ui_theme.xml` changes only window presentation to the Soft default and enables system-bar background drawing. Screenshot review caught black bars with unreadable light-mode icons; final native captures show readable status/navigation bars.

[First selector failure](evidence/terminal-workspace-selector-failure.log), [palette navigation failure](evidence/terminal-palette-navigation-failure.log), [focused selector failure](evidence/palette-workspace-selector-failure.log).

**OBSERVED**: Opening the Activity neither enables phone tools nor launches consent. The enable/disable action remains explicit. Folder revocation releases the persisted document grant without deleting folder data; restoration requires selecting it again. App settings intents derive their identity from `packageName`; Kotlin class identities use `ComponentName(this, serviceClass)`.

**OBSERVED**: Status refresh runs on return and once per second only while resumed. Android's permission/settings state supplies grant and revocation status; service connection status remains distinct. Missing runtime/bridge yields a recovery notice and disables bridge-dependent actions. Location denial and permanently denied permission recovery have explicit copy and app-settings routes. Cooperating-app drafts and pending capture identifiers survive Activity recreation; consent Intent data is not saved.

**OBSERVED**: The `request` and `requestId` launch extras remain supported. Capture requests open the capture page, folder requests open the folder page, and both still require user interaction. A matching offered capture identifier is reused; expired offers are rejected without substituting a different task's capture. Leaving or declining an unconsented offer calls `cancelConsent`; configuration recreation does not cancel it. Returned consent still requires `capturePending` before starting the existing foreground capture service. Failed service launch cancels consent. The bridge owner's read-only `captureResult` accessor supplies actual pending/capturing/ready/denied/failed/expired state; Android consent alone never produces a success message. A stopped or replaced bridge cannot regain authority through this UI.

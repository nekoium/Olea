# Olea 0.1.0

Bring Pi, Codex and Claude Code to your Android phone. Agents run locally with a packaged Linux environment; model replies use your configured provider. No running desktop, root access or active ADB connection is required for normal use.

This is the first public MVP. Tested on a physical **Android 14 ARM64** phone. The APK declares Android 8/API 26 as its minimum, but other Android versions and devices have not been accepted. Use an ARM64 device; no x86_64 binary is published in this release.

## First run

Download and open the APK, allow installation from your chosen browser/file manager if Android asks, then open Olea. Choose your agent and workspace, prepare the environment, install the agent and enter your provider URL, model ID and API key. Optional phone access can be skipped. First preparation and agent installation need network access and additional storage.

Try asking the agent to create `hello.txt`, write a short message and read it back. Pi and Codex custom providers use the OpenAI Responses API; Claude Code uses Anthropic Messages. Provider charges and API access are separate from Olea.

## Included

Flat native interface, resumable setup, fixed-agent saved conversations, managed workspaces, direct primary-storage folder connections, file previews, provider/agent management, streaming replies and tool activity, per-turn cancellation and global STOP. Phone tools use explicit enabling plus Android permissions and special access.

Physical acceptance covered native connectivity for all three agents. Pi also completed workspace read/write, streaming cancellation, saved-context continuation, browser opening and an Accessibility inspection/click. Connected-folder checks covered normal grant/denial, actual guest realpath/read/write and host readback, revocation and missing-folder recovery.

## MVP limits

- The terminal is experimental. Real PTY commands, control input and lifecycle checks passed, but its display/keyboard behavior has required device-specific fixes. A blank terminal does not prevent conversation, file or phone-tool use.
- Android can end background processes. Saved conversations persist; shells do not survive process death. Inspect results before resending interrupted work. Reconnecting does not replay earlier prompts.
- At most two agent sessions and four terminal sessions can remain connected. Disconnect or stop an existing session to free a slot.
- Connected Android folders require broad all-files access and agent edits affect the original files directly. Shared storage does not guarantee executable bits, symlinks, package installation or native builds. Workspaces organize files; they do not isolate agents from one another.
- Screen capture returns status and image metadata, not image pixels to the model. Accessibility coverage depends on the target app. STOP cannot undo an action or file change already completed.
- Built-in backup/export, scheduled tasks, reminders, alarms and general phone-folder cleanup are not included. Uninstalling or clearing app storage deletes local data. Back up important files separately.
- The public package is `dev.olea`, separate from earlier debug `dev.olea.app`; it does not import development-build data. Ordinary compatible signed updates preserve public-app storage.

The app does not include provider credits or a spending cap. Agents have broad command/file authority within Android's granted access. Keep credentials and private content out of feedback screenshots and logs.

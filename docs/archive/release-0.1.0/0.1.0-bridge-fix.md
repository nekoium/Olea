# Olea 0.1.0 phone bridge transport fix

**OBSERVED**: The independent security worker reproduced S1 (medium availability): four unauthenticated idle loopback sockets delayed an authorized call beyond its 10-second client timeout. Its alert, report and reproducer remain unchanged: `.setup/release-010/security-alert.md` and `.setup/release-010/security/bridge-probe.mjs`.

**USER DECISION**: The dispatched assignment authorized a bounded transport fix without an approval gate, with ownership limited to `PhoneBridge.kt`, a new local diagnostic and this report. The coordinator additionally requested `captureResult(id)` for the separate phone UI worker, as recorded in `.setup/release-010/phone-ui-needs.md`.

## Change

**OBSERVED**: The accept loop dispatches connections to an eight-worker `ThreadPoolExecutor` with `SynchronousQueue` and its default rejection policy. There is no pending transport task queue. Saturation closes the newly accepted socket immediately. A socket set records admitted connections; admission, rejection cleanup and set removal share its monitor. Worker completion closes the socket and removes it even when handling throws.

**OBSERVED**: `close()` closes the listener first, then all admitted sockets and the transport executor under the admission monitor. An accept racing shutdown observes the closed listener or has its socket included in cleanup. Native STOP retains its existing authority-revocation behavior and keeps transport available for status reads. Closing transport does not interrupt or replace a potentially stuck file-provider worker.

**OBSERVED**: Android effects still pass through the existing main-thread dispatch, authority lock and epoch check. File effects retain the existing single file worker, no waiting queue, busy guard and bounded cancellation executor. HTTP bearer comparison (`MessageDigest.isEqual`), header/body limits, read/deadline checks, per-socket timer and existing operation deadlines are unchanged. Concurrent transport does not add another Android effect executor.

**OBSERVED**: The UI accessor returns a defensive JSON copy only for the matching enabled, open capture request. Matching requests without metadata return `consent_pending` or `expired`; unknown/stopped requests return null. Reading the accessor does not change capture authority or treat consent as completed capture.

## Focused checks

**OBSERVED**: Run `node .setup/release-010/bridge-fix/probe.mjs` from the repository root. The task-local script extracts the current transport fields, accept loop, socket cleanup, HTTP handler, `onMain`, authority epoch guard, capture-pending method and new accessor. It compiles those source sections with the existing standalone Kotlin compiler and runs them on the host JVM. Line endings are normalized for compilation; the recorded SHA-256 covers original source bytes. Android operations and `org.json` are stubbed; the JSON stub uses the locally available Groovy JSON parser/serializer.

**OBSERVED**: Final focused run passed against `PhoneBridge.kt` SHA-256 `ac3534cae3f0e6dc6655fcf588f78c3e059878e3eb0afd05da871e057747b4f4`:

- Four concurrent authorized effect requests succeeded with a maximum of one simulated main-thread effect at a time.

## Limits

**OPEN**: Eight continuously occupied transport slots can still reject legitimate arrivals. The change removes serial starvation from several idle peers and bounds resource consumption; it does not guarantee availability under sustained connection saturation. The listener also retains its existing requested kernel backlog of four and may briefly hold one newly accepted socket while deciding admission.

**OPEN**: No whole-project build, Android device, provider calls, real Android effects, real file provider or final APK checks ran in this assignment. The simulated main thread and JSON implementation establish the bounded host behavior described above, not device acceptance. Existing file-worker bounds and full native STOP behavior were inspected in source, not independently re-executed against Android. The coordinator owns integration/build validation, the progress-record entry and final security acceptance.

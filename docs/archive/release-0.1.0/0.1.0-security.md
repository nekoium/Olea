### Connected-folder boundaries

**OBSERVED**: `AndroidSharedFolders` rereads Android all-files status, storage state and directory accessibility for each availability check. It requires a direct canonical absolute path under primary shared storage, rejects bind/TSV delimiters and control characters, and excludes restricted Android/data and Android/obb paths. `WorkspaceFolders` validates private registry identity, permits only a new empty nondefault workspace connection, keeps the connected source mapping immutable, and writes a synced binding snapshot. It replaces only an empty private placeholder directory with a checked marker file; unavailable connected paths therefore cannot silently become managed workspace directories.

**OBSERVED**: `Environment.builder()` writes fresh bindings before process launch. `runtime/linux.sh` passes bind pairs as quoted positional arguments rather than shell evaluation, validates guest IDs/source syntax and skips unavailable sources. Backend `realpath`, root-relative containment and directory checks reject an unbound marker file as cwd. Native `taskWorkspacePath()` additionally requires the connected guest path to have been included in the launch snapshot. Conversation start, prompt, workspace command, terminal creation/input and accepted Codex approval call these current availability checks. Managed workspaces do not require all-files permission.

**OPEN**: These checks do not provide a per-command filesystem sandbox or instantaneous revocation of an existing running shell/agent. There is no demonstrated active-process revocation observer here; existing processes and open descriptors remain subject to Android's actual filesystem enforcement until STOP/exit. Preflight checks also do not eliminate directory-replacement/time-of-check races. PRoot and same-UID full-access agents are not isolation from app-owned homes, credentials, other mounted workspaces or Android-accessible paths. Terminal child environment filtering prevents direct provider/bridge variable inheritance, not reading same-UID credential files. These are scope limits, not a newly demonstrated permission bypass; do not describe connected workspaces as isolated or live revocation as immediate process cancellation.

**OBSERVED**: The factory serves only the exact APK terminal document URL as main-frame GET plus exact xterm JS/CSS subresources; every other intercepted URL receives 403. **OBSERVED**: Native output/key scripts use `JSONObject.quote`; the trusted document routes output to `terminal.write`, not `innerHTML`, `document.write`, dynamic script generation or URL navigation. No custom HTML-producing terminal handler or untrusted document loader was found in this reviewed path. This review found no demonstrated PTY-output-to-JavaScript injection route. It is not a comprehensive xterm vulnerability assessment.

**OPEN — failed defense-in-depth check**: The coordinator reports that real factory allowlist/WebSocket checks pass but an injected `srcdoc` frame can execute and mutate its parent despite response `frame-src 'none'; child-src 'none'`.

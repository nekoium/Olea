## Recombination and installation

**OBSERVED**: ELF dynamic entries from both actual pinned PRoot binaries require `libtalloc.so.2`, `libandroid-shmem.so` and `libc.so`. Both actual talloc binaries advertise SONAME `libtalloc.so.2`. `runtime/linux.sh` preloads the packaged talloc/shmem libraries and launches PRoot. These observations support the documented replacement mechanism; they are not a modified-library execution test.

[RELINKING.md](../../runtime/source/RELINKING.md) gives target-specific Termux build commands, local modified-source inputs, exact output-to-APK filename mappings, library compatibility requirements, and Info-ZIP/zipalign/apksigner commands for producing a newly signed modified APK. The recipe deliberately runs after the original runtime build because `runtime/build.sh` selects and restores pinned upstream bytes. APK replacement does not require the publisher's signing key. Android rejects a differently signed update over the official app; instructions preserve that limitation and describe a separate application ID/source build or installation on a device without Olea. No destructive uninstall is performed or advised without verified data export.

**OPEN — unmeasured behavior**: No modified talloc build, modified APK installation or device execution was run by this worker. These are verification limits, not fabricated acceptance results. The prepared source-code route does not depend solely on claiming Android's bundled shared libraries are freely replaceable in place.

For LGPL guest libraries, the companion likewise includes exact source and build rules. Guest package changes can be made in a writable runtime using normal package tools; rebuilding a guest image requires updating its `assets/hashes.txt` entry before re-signing the APK. The native talloc-only replacement procedure leaves guest assets and their hashes untouched.

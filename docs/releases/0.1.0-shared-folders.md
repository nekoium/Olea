## Implemented source

- [AndroidSharedFolders.kt](../../android/app/src/main/java/dev/olea/app/AndroidSharedFolders.kt) checks Android 11+ ordinary all-files special access, primary-storage mount state, canonical paths and read/write/list access. It distinguishes permission required, not granted, revoked, unavailable/read-only storage, missing folder, invalid path and inaccessible folder. Checks never create missing folders.
- [SharedFolderActivity.kt](../../android/app/src/main/java/dev/olea/app/SharedFolderActivity.kt) reuses FlatUi, lists native folders on `Dispatchers.IO`, offers explicit Android settings navigation, rechecks on foreground return and preserves navigation through rotation. Cancel returns no selection. Connect this folder returns `EXTRA_PATH` and `EXTRA_NAME` with `RESULT_OK`, without registry writes.
- Create Olea folder explicitly creates one primary-root `Olea` child. An existing directory is reused unchanged; an existing file causes an error. Opening/browsing/checking/selecting does not create shared folders. The access helper does not create write-probe files.

**OBSERVED**: API <30 returns unsupported; managed workspaces remain the route on older Android. Only direct canonical paths under Android's primary root pass. Nonprimary/cloud/provider paths, redirected paths, parent segments, colon/backslash/control characters and Android-restricted `Android/data`/`Android/obb` trees fail. Package URI uses actual `context.packageName`, compatible with public applicationId `dev.olea` and Kotlin namespace `dev.olea.app`.

**OBSERVED**: Android has no separate denial result for this settings page. Denied means requested but not granted; revoked requires a previously observed grant. Available means preliminary Android access, not verified PRoot/runtime readiness or guaranteed write success.

Current runtime has no mapped access guards and SessionStore.workspacePath still invokes managed directory creation. Integrator must coordinate these: omitting inaccessible bindings without guards and placeholder changes permits private-folder fallback. Integrator must prevent private fallback or add concrete bind-identity verification and establish it on the physical phone. Do not claim fail-closed behavior from status checks alone.

**OBSERVED**: Runtime connect currently creates/reads/deletes `.olea-access-<uuid>` using exclusive creation, returning error if cleanup fails. New helper/Activity does not probe. Integrator owns ensuring explicit connection authorization covers that bounded host write or replacing it with manager-authorized acceptance fixtures. No shared-directory creation/deletion may occur except explicit Create Olea folder.

**OPEN**: `WorkspaceFolders` private record read-modify-write is currently unsynchronized across instances. Preserve atomic saves and coordinate writers during integration. Connected host mappings must remain immutable for their workspace IDs; changed host locations require new workspace/conversation identities.

## Implemented behavior

- `AndroidSharedFolders` checks ordinary Android 11+ all-files special access, primary storage mount state, direct canonical path and read/write/list access. It distinguishes permission required, not granted, revoked, read-only/unavailable storage, missing folder, invalid path and inaccessible folder. It excludes nonprimary/cloud/provider paths, redirected paths, parent segments, bind/TSV delimiters and restricted Android/data or Android/obb trees. These are preliminary access checks, not a hidden write test.
- `SharedFolderActivity` is registered, uses FlatUi and lists native folders on IO. It offers explicit Android settings, foreground rechecks, cancel and Connect this folder. Create Olea folder creates one visible primary-root child only on tap; existing directories/content are reused and existing files are not replaced. Package URIs use actual applicationId, compatible with `dev.olea` and Kotlin namespace `dev.olea.app`.
- Workspace creation and onboarding launch the Activity through a result contract. `RuntimeService.createConnectedWorkspace` checks stopped state under the service lock and validates access before creating private metadata. Connection precedes conversations. Existing workspace mappings are immutable; default or nonempty/in-use workspaces cannot be rebound. Failed connection remains an error and preserves data.
- `WorkspaceFolders` strictly parses its existing mapping record, validates known IDs and path values, synchronizes instances, and saves atomically. It preserves unavailable/missing mappings. Mapping `status` reports helper state/message; native file viewing uses the freshly validated mapped host root rather than private files.
- Access is rechecked before open/resume, prompt including connected sessions, workspace-shell, terminal creation/input and accepting an execution approval. Checks precede working/opening state changes and prompt journaling. STOP/close/cancel remain available without renewed access. If a folder was unavailable at environment launch, later task start asks for an explicit STOP/restart after access restoration.
- Native workspace files refresh on foreground return and explicit Refresh, resolve mapped host root on every read/list, retain canonical descendant containment and bound previews to 256 KB even if the file grows. Revoked/missing access shows recovery/settings; canceled coroutines do not become read errors.
- Workspace details show connected host and guest paths, plus specific access recovery. Onboarding source labels and access recovery reflect saved mappings.
- At the manager's request, stopped-turn copy now distinguishes a still-connected canceled turn (send a follow-up) from disconnected/global STOP (reconnect). Behavior is unchanged.

**OBSERVED**: Android has no separate denial result for this settings page. Denied means requested but not granted; revoked requires a previously observed grant. API <30 reports unsupported instead of substituting legacy permission behavior. Normal settings is the only grant route; no ADB/appops grant or background auto-grant was added.

## Preventing managed-folder fallback

**OBSERVED**: Existing code created an empty private directory for a new workspace. PRoot can warn and continue when an external bind fails, which would make that directory an unsafe substitute cwd.

**OBSERVED**: Connection now replaces only that empty app-private placeholder directory with a recognizable **regular file**. The mapping remains immutable; actual shared folders and their content are not changed. Existing nonempty private directories, redirected paths or unexpected placeholder files produce a recovery error and are preserved. Interrupted setup can recreate a missing marker; unrecognized private data is never overwritten.

**OBSERVED**: Binding snapshots leave those file markers in place for every registered connected workspace, including inaccessible ones. Only accessible sources enter the private source-TAB-guest snapshot. Linux validates exact guest IDs, source syntax and private file marker, preserves each quoted bind after the fixed `/workspace` bind, and skips a source that disappears before launch. An omitted or failed bind leaves a regular file, so existing backend `stat(...).isDirectory()` validation rejects it as cwd. Native file viewing never reads that marker as the connected source.

**OBSERVED**: This permits managed workspaces and agent maintenance to proceed while an external folder is unavailable, without deleting its metadata or silently substituting private storage. SessionStore remains unchanged; connected runtime paths go through WorkspaceFolders, avoiding SessionStore's managed-directory creation method.

**OPEN**: Physical PRoot acceptance must establish binding a host directory over this private file marker, guest realpath, underlying file preservation and behavior if PRoot skips a bind. If this PRoot version cannot bind over the file marker, connected starts must fail; do not restore a directory fallback or weaken backend checks as a workaround. Provider/OS access can race after any precheck; Android still enforces its actual permissions.

Continue the direction. Pi + Codex look promising; all agents and real phones remain unproved.

“Maintain the Android runtime, avoid private agent ports” looks feasible for the tested Pi and Codex workflows. Both ran unchanged upstream releases on the Android emulator. Confidence is moderate in this direction, insufficient for a production or universal-agent claim.

We still own the runtime, phone tools and adapters. Ordinary updates must remain possible; compatibility with future releases is not guaranteed.

What we would still have to maintain

Ordinary install/update: use the agent publisher’s normal packages. Private port: modify and rebuild the agent for Olea, then repeat that work for new releases. Current successful workflows need no private source patches or private protocol shims.

Allowed ongoing work: package the Linux runtime, repair Android startup/cleanup/recovery, and maintain our adapters and phone tools. Supported integration APIs reduce porting work; they do not eliminate agent-specific work.

Decisions that matter now

  1. Continue bounded feasibility work. Finish the current phone/recovery checkpoint; then prioritize real-phone and ordinary-update evidence before broad production commitments.
  2. Keep the trust tradeoff explicit. Full-access Codex is already selected. Reopen it only if agent isolation becomes a product requirement; that changes the feasibility question.
  3. Gate support claims on workflows. Pi + Codex are the evidence leaders. Claude remains a release risk. If it cannot meet acceptance, decide scope or date explicitly.

Reconsider the direction if: normal supported-agent updates repeatedly need agent source patches, or physical-phone resource/lifecycle limits make core workflows unusable. These are proposed decision gates, not newly agreed scope.

Runtime maintenance and safety limits

Actual target-36 Kotlin service execution uses stock PRoot/Ubuntu and upstream Node/Git/npm. Stock Pi 1.5.2 and Codex 0.167 completed Unix, phone and resume workflows. The current-runtime Pi update proof is adjacent-version preservation; older Pi updates are historical evidence. Ordinary Codex updates and broad runtime/failed/interrupted-update preservation are not established.

Kotlin enforces measured selective location/notification/Accessibility revocation and native STOP. Runtime startup, timeout, teardown and combined active backend/app interruption plus explicit recovery have bounded evidence, with preservation hashes and no observed uncertain-effect replay. Arbitrary unseen forks, automatic backend-only recovery, general background/reboot behavior and model-turn cancellation remain gaps. A conservative process-scanner failure is retained; later PID absence did not rewrite its result.

Codex uses stock danger-full-access / approval never, explicitly selected. PRoot and shared UID do not protect Olea-readable credentials from an agent. Phone permission authority and hostile-agent containment are separate properties.

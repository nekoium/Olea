## Cleanup diagnosis for runtime owner

`CodexProcess.stopInner()` snapshots numeric parentage only at stop, then signals the selected identities. Already reparented Git children cannot be rediscovered as app-server descendants by that snapshot. It always returns `descendantsVerified:false`; root exit is separately tracked. `snapshotOwnedTree` correctly guards UID/starttime and has finite entry/time bounds, but its source explicitly lacks ownership of prior reparented children.

`RuntimeProbe.run()` owns the shell `Process`, records `childPid:null`, and on timeout only calls `destroyForcibly()` on that shell before bounded pipe draining. `RuntimeService.stopBackend()` writes stop then immediately destroys its wrapper and clears `backend`; `backendRunning:false` therefore cannot independently prove wrapper or descendant exit. These source paths explain proof gaps, not a definitive attribution of the historical Git leak. A minimal runtime fix should retain identities while ancestry is still observable and report settled cleanup separately, with focused deterministic fixtures before any new prompt.

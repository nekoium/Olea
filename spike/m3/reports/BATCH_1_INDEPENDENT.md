## Source review findings for runtime owner

1. **Early STOP can miss a newly launched probe.** `RuntimeProbe.cancel()` does nothing while `owned` is still null, including the interval between `OwnedProcess.launch(...)` and assignment. Within `OwnedProcess`, `stop()` can run before observer inserts root identity: `snapshot()` returns with empty inventory, `stopping=true` becomes permanent, and repeated stop calls only return results without retrying cleanup. The Java child can continue until its deadline. Current cancellation test waits1500ms and an already-written started marker; it does not exercise either startup race. Fix should latch cancellation for that launch and establish root ownership or an explicit bounded failed-start cleanup before declaring stop settled. Never convert empty inventory to verified exit.
2. **Service destruction does not cancel probes.** `RuntimeService.onDestroy()` disables phone and stops capture/backend but does not invoke `RuntimeProbe.cancel()`. Its STOP paths now do. Distinguish controlled service destruction from whole-process force-stop; current recovery kills app only after all work settled. Scope a deterministic teardown check if this path is retained.
3. **Capture has no delivered image tool yet.** `phone_capture_result` exposes metadata only. Source excludes oracle readers and shell/ADB endpoints, but image metadata alone cannot establish a captured harmless screen or enable visual interpretation. Independent PNG inspection remains required for direct capture acceptance; do not allocate a model prompt expecting image access from this tool.
4. **Deployed-byte provenance remains qualified.** Final manifest pins raw working-tree source hashes; all but new `OwnedProcess.kt` differ from Git blobs solely by CRLF versus LF, independently reconstructed and recorded in assessment. No bytes were normalized. It records backend payload SHA256, but does not inventory individual deployed `dist/*.js` bytes or retain that payload in Git. Final source is not retroactive source proof for a01/a02 APKs. Preserve exact payload/installed APKs and add owner-side deployment hashes when a new batch is actually deployed, without claiming a new device observation here.
